# BuddyStudy AdServer를 어떻게 설계했을까

> 공개 질문 사이에 광고 한 개를 자연스럽게 넣고, 불편한 광고는 줄이는 서버가 필요했다.

## 1. 어떤 광고가 필요했나

처음 필요했던 광고는 단순한 배너가 아니었다.

- 공개 질문이 4개 이상일 때만 중간에 광고 한 개를 넣는다.
- 광고 이미지와 제목, 쿠팡 이름, 대가성 문구를 함께 보여준다.
- 누르면 쿠팡 주소로 이동한다.
- 관심 없음을 누르면 그 사용자에게 다시 보여주지 않는다.
- 앱이 아니라 서버가 광고와 위치를 결정한다.

즉, 질문처럼 자연스럽게 보이지만 광고임은 분명한 네이티브 광고가 필요했다.

## 2. AdServer를 어떻게 설계했나

AdServer는 지금 보여줄 수 있는 광고만 남기고, 점수를 매긴 뒤, 공개 질문과 광고를 하나의 목록으로 내려준다.

~~~mermaid
flowchart LR
    A[광고 등록] --> B[캠페인 저장]
    C[공개 질문 요청] --> D[후보 광고 걸러내기]
    B --> D
    E[전달 노출 클릭 관심 없음 기록] --> F[최근 30일 통계]
    F --> D
    D --> G[광고 점수 계산]
    G --> H[질문과 광고를 한 목록으로 응답]
    H --> I[iOS는 받은 순서 그대로 표시]
    I --> E
~~~

서버가 맡는 일은 다섯 가지다.

1. 운영 시간과 대상이 맞는 광고만 남긴다.
2. 너무 자주 보여준 광고를 뺀다.
3. 최근 반응을 한 번에 읽어 점수를 계산한다.
4. 대부분은 1위 광고를 고르고 가끔 다른 광고도 시험한다.
5. 전달, 실제 노출, 클릭, 관심 없음을 따로 저장한다.

## 3. 어떤 자료를 참고했나

- [Google Ads 경매 방식](https://support.google.com/google-ads/answer/6366577?hl=ko)은 광고를 먼저 걸러낸 뒤 관련성, 품질, 상황을 함께 평가하는 방식을 참고했다.
- [카카오 광고추천팀 소개](https://tech.kakao.com/posts/524)는 클릭과 전환 예측, 탐색, 랭킹, 실시간 서빙, 통계 파이프라인을 한 시스템으로 운영하는 관점을 참고했다.
- [Google Ads 입찰 목표 설명](https://support.google.com/google-ads/answer/2459326?hl=ko)은 전달 수와 실제로 화면에 보인 노출 수, 클릭 수를 구분하는 기준을 참고했다.

BuddyStudy는 광고 경매나 머신러닝까지 도입하지 않았다. 현재 규모에 맞게 설명할 수 있는 점수 방식부터 시작했다.

## 4. 용어를 아주 짧게 정리하면

| 용어 | 뜻 |
| --- | --- |
| 캠페인 | 관리자가 등록한 광고 한 묶음 |
| 후보 광고 | 지금 보여줄 조건을 통과한 광고 |
| 랭킹 | 후보마다 점수를 매겨 순서를 정하는 일 |
| 전달 | 서버가 광고를 목록에 넣어 내려준 상태 |
| 실제 노출 | 광고의 절반 이상이 화면에 1초 동안 보인 상태 |
| 클릭 | 사용자가 광고를 눌러 쿠팡으로 이동한 행동 |
| 관심 없음 | 해당 광고를 앞으로 보여주지 말라는 행동 |
| 탐색 | 새 광고도 반응을 모을 수 있도록 가끔 시험하는 것 |

## 5. 광고 점수는 어떻게 계산하나

현재 점수는 아래 기준을 더하고 뺀다.

~~~text
광고 점수
= 관리자가 정한 우선순위
+ 로그인 상태에 맞는 정도
+ 최근 클릭 비율
+ 새 광고를 시험할 기회
+ 오랫동안 나오지 않은 광고에 주는 기회
- 오늘 이미 전달한 횟수
- 관심 없음 비율
~~~

기록이 적은 새 광고는 한두 번의 클릭만으로 1위가 되지 않도록 평균값을 조금 섞는다.

- 85퍼센트는 점수가 가장 높은 광고를 고른다.
- 15퍼센트는 상위 세 개 중 다른 광고를 시험한다.

항상 1위만 보여주면 새 광고는 판단할 자료를 모을 수 없다. 반대로 전부 무작위로 고르면 반응이 나쁜 광고도 계속 나온다. 그래서 두 방식을 섞었다.

## 6. 어떤 기록을 저장하나

광고를 고를 때마다 선택 기록을 저장한다.

~~~text
서버가 광고 선택
→ 전달 시간 저장
→ 화면에 1초 이상 보이면 실제 노출 시간 저장
→ 누르면 클릭 시간 저장
→ 관심 없음을 누르면 사용자별 제외 기록 저장
~~~

같은 실제 노출 요청이 여러 번 와도 최초 한 번만 저장한다. 클릭도 같은 광고 선택 번호를 기준으로 한 번만 반영한다.

최근 30일 기록은 광고 번호를 묶어서 한 번에 읽는다. 광고가 늘어나도 광고마다 데이터베이스를 다시 조회하지 않기 위해서다.

## 7. 어드민에서는 무엇을 보나

| 값 | 확인할 수 있는 것 |
| --- | --- |
| 전달 수 | 서버가 광고를 몇 번 골랐는가 |
| 실제 노출 수 | 사용자가 화면에서 실제로 본 광고는 몇 개인가 |
| 클릭 수 | 쿠팡 주소를 연 횟수는 몇 번인가 |
| 노출 뒤 클릭 비율 | 실제로 본 사람 중 몇 명이 눌렀는가 |
| 관심 없음 수 | 불편하다고 판단한 사용자가 얼마나 되는가 |

클릭 수만 높다고 좋은 광고로 판단하지 않는다. 관심 없음도 함께 늘고 있는지 봐야 한다.

## 8. 지금 구현된 범위

- 백엔드가 광고를 고르고 위치까지 정한다.
- iOS는 공개 질문과 광고가 섞인 목록을 그대로 그린다.
- 쿠팡 이미지와 주소, 대가성 문구를 어드민에서 관리한다.
- 사용자는 관심 없음을 선택할 수 있다.
- 전달, 실제 노출, 클릭, 관심 없음 통계를 분리했다.
- 사용자의 답변 내용과 개인 학습 내용은 광고 점수에 사용하지 않는다.

현재는 이해하기 쉬운 규칙 기반 랭킹이다. 데이터가 충분히 쌓인 뒤에야 개인화나 머신러닝을 검토할 수 있다. 먼저 정확한 기록을 쌓는 것이 우선이라고 판단했다.

## 9. 한눈에 요약

BuddyStudy AdServer의 핵심은 단순하다.

1. 보여줄 수 없는 광고를 먼저 뺀다.
2. 남은 광고에 최근 반응을 반영해 점수를 매긴다.
3. 공개 질문과 광고를 한 목록으로 내려준다.
4. 앱은 순서를 바꾸지 않는다.
5. 전달, 실제 노출, 클릭, 관심 없음을 나눠 다음 선택에 사용한다.

처음부터 복잡한 머신러닝을 넣기보다, 왜 광고가 선택됐는지 설명할 수 있고 운영자가 직접 확인할 수 있는 구조부터 만들었다.
