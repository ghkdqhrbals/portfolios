# 일단 무엇을 광고 노출로 볼 것인가?

공개 질문 피드 사이에 광고를 자연스럽게 섞어서 보여주는 기능을 만들고 있다.

처음에는 `광고마다 우선순위를 주고 반응이 좋은 광고를 위에 올리면 되지 않을까?` 라고 생각했다. 그런데 조금만 더 생각해보니 반응이 좋다는 기준부터 애매했다.

서버가 광고를 내려줬다고 사용자가 광고를 본 것은 아니다. 피드 20번째에 광고를 넣었는데 사용자가 5번째까지만 보고 나갔다면 이것을 노출로 집계하면 안된다. 마찬가지로 광고를 눌렀다고 구매까지 이어진 것도 아니다.

결국 광고 랭킹 이전에 아래 이벤트들을 분리해서 정의해야했다.

```text
광고를 넣을 수 있는 요청
→ 노출 가능한 광고 후보
→ 서버가 선택한 광고
→ 화면에 실제로 보인 광고
→ 사용자가 클릭한 광고
→ 가입·구매까지 이어진 광고
```

이 단계들이 섞이면 CTR, CVR, ROAS 같은 지표를 아무리 계산해도 전부 잘못된 값이 된다.

# 다른 광고 플랫폼은 어떻게 하고있을까?

정확한 광고 랭킹 모델과 가중치는 각 회사의 핵심 영업비밀이라 전부 공개되어 있지는 않다. 그래도 Google, 카카오, 당근의 공식 자료를 찾아보면 어떤 데이터를 수집하고 어떤 순서로 광고를 고르는지는 어느정도 확인할 수 있다.

## Google

Google 광고 경매는 단순히 입찰가가 높은 광고를 선택하지 않는다.

* 광고주의 입찰가
* 예상 클릭률
* 광고와 검색 의도의 관련성
* 광고와 랜딩 페이지의 품질
* 광고가 노출되기 위한 최소 품질 기준
* 검색어, 위치, 기기, 시간
* 다른 광고와 검색 결과의 경쟁 상황

을 매 경매마다 다시 계산한다.

그래서 더 많은 돈을 내는 광고라고 무조건 위에 노출되는 것은 아니다. 사용자의 검색 의도와 더 잘 맞고 랜딩 페이지의 품질이 좋다면 더 낮은 입찰가로도 상위에 노출될 수 있다.

* [Google Ads 경매 동작 방식](https://support.google.com/google-ads/answer/6366577?hl=en)

전환 최적화에서는 기기, 위치, 시간, 실제 검색어, 광고 소재, 언어, 브라우저, OS 같은 값을 따로 보는 것이 아니라 조합해서 본다.

예를 들어 `모바일 사용자의 전환율이 낮다` 로 끝나는 것이 아니라 `평일 아침 + 모바일 + 특정 지역 + 특정 광고 소재` 에서는 전환율이 달라질 수 있다는 식이다.

* [Google Ads 자동 입찰과 경매 시점 신호](https://support.google.com/google-ads/answer/10964872?hl=en)

그리고 광고에서는 단순히 광고 A가 B보다 위에 있는지만 맞히는 것으로는 부족하다. 모델이 `클릭 확률 10%` 라고 예측했다면 실제로도 비슷하게 10%가 클릭해야 입찰가와 곱해서 예상수익을 계산할 수 있다. 이를 확률 보정, Calibration이라고 한다.

* [Google CTR 예측 시스템](https://research.google/pubs/ad-click-prediction-a-view-from-the-trenches/)
* [광고 랭킹 모델의 확률 보정](https://research.google/pubs/scale-calibration-of-deep-ranking-models/)

## 카카오

카카오는 정확한 랭킹 점수식 대신 어떤 광고 반응을 수집하고 타게팅에 활용하는지 공개하고 있다.

* 광고 클릭, 재생, 메시지 열람, 전환
* 픽셀과 SDK로 수집한 방문, 가입, 장바구니, 구매
* 성별, 연령대, 지역, 기기
* 관심사와 업종
* 카카오쇼핑 구매, 장바구니, 관심상품 행동
* 기존 광고 반응 사용자와 고객 식별자

특히 이전 광고를 클릭했지만 전환하지 않은 사용자, 광고를 재생했지만 클릭하지 않은 사용자처럼 반응 데이터를 조합해서 타겟을 만들 수 있다.

* [카카오 광고반응타겟](https://developers.kakao.com/docs/ko/kakaomoment/target-reaction-mgmt)
* [카카오모먼트 타게팅](https://kakaobusiness.gitbook.io/main/ad/moment/messagead/channelmessage/new/send)

집계 지표도 노출과 클릭에서 끝나지 않는다.

* 노출수, 도달수, 클릭수, CTR
* 노출당 비용, 클릭당 비용, 도달당 비용
* 1일/7일 가입, 구매, 장바구니, 앱 설치
* 구매 금액과 ROAS
* 메시지 발송, 열람, 실패, 재생

처럼 전환이 발생하기까지의 기간도 나누고 있다.

* [카카오모먼트 지표 정의](https://developers.kakao.com/docs/ko/kakaomoment/type-info)

여기서 가장 눈에 들어온 것은 노출 기준이었다. 카카오는 디스플레이 광고의 50% 이상이 화면에 1초 이상 보였을 때 노출로 집계한다. 더블클릭이나 인위적인 반복 클릭도 유효 클릭에서 제외한다.

* [카카오모먼트 노출·클릭 집계 기준](https://kakaobusiness.gitbook.io/main/ad/moment)

## 당근

당근의 공개 자료가 내가 만들고 있는 네이티브 광고 구조와 가장 비슷했다.

당근 AdServer는 아래 순서로 광고를 선택한다.

1. 광고가 표시될 지면을 확인한다.
2. 광고를 볼 사용자의 지역, 연령대, 관심사 등을 추론한다.
3. 예산이 남아있고 지면, 사용자, 시간 타게팅이 맞는 광고만 가져온다.
4. 후보 광고를 eCPM 기준으로 경쟁시킨다.
5. 선택한 광고에 성과 추적 링크를 붙인다.
6. 이후 노출, 클릭, 가입, 구매를 측정한다.

여기서 eCPM은 광고를 1,000번 노출했을 때 기대할 수 있는 수익이다. CPC 광고라면 대략 아래와 비슷하게 볼 수 있다.

```text
예상 eCPM = 클릭당 광고 가치 × 예상 클릭률 × 1,000
```

전환이나 구매 수수료를 기준으로 한다면 아래에 더 가깝다.

```text
예상 광고 가치 = 클릭 확률 × 클릭 후 구매 확률 × 예상 수수료
```

* [당근 AdServer가 광고를 선택하는 방식](https://careers.daangn.com/blog/post/%EB%8B%B9%EA%B7%BC-%EA%B4%91%EA%B3%A0%EC%8B%A4-%EA%B0%9C%EB%B0%9C%EC%9E%90-%EC%84%9C%EB%B2%84-%EC%97%94%EC%A7%80%EB%8B%88%EC%96%B4-dsp/)

또한 당근은 새로운 광고 모델을 기존 모델과 비교할 때 실험 요인만 다르게 하고 다른 조건은 동일하게 맞춘다. A/B 테스트 결과가 섞이지 않도록 모델, 피처, 로그, 실험군을 하나의 광고 추천 플랫폼에서 관리하는 방식이다.

* [당근 광고 추천 플랫폼과 A/B 테스트](https://careers.daangn.com/blog/post/%EB%8B%B9%EA%B7%BC-%EA%B4%91%EA%B3%A0%EC%8B%A4-%EC%97%94%EC%A7%80%EB%8B%88%EC%96%B4-%EC%BB%A4%EB%A6%AC%EC%96%B4/)

# 어떤 이벤트를 저장할 것인가?

먼저 하나의 `view` 이벤트에 모든 의미를 넣으면 안된다. 서버가 내려준 것, 화면에 보인 것, 사용자가 누른 것을 따로 저장해야한다.

| 이벤트 | 집계 기준 | 사용하는 곳 |
| --- | --- | --- |
| `OPPORTUNITY` | 광고를 넣을 수 있는 피드 요청 발생 | 광고 재고와 fill rate |
| `ELIGIBLE` | 캠페인이 예산·시간·타게팅 필터 통과 | 필터 탈락 원인 분석 |
| `SELECTED` | 서버가 광고를 피드 응답에 포함 | 선택률, 랭킹 결과 분석 |
| `IMPRESSION` | 앱에서 광고 셀이 렌더링됨 | 렌더링 누락 확인 |
| `VIEWABLE_IMPRESSION` | 화면 50% 이상이 1초 이상 표시 | CTR의 실제 분모 |
| `CLICK` | 사용자가 광고를 눌러 딥링크 이동 | CTR, 클릭당 비용 |
| `LANDING` | 외부 페이지가 정상적으로 열림 | 딥링크·외부 페이지 실패 확인 |
| `CONVERSION` | 가입·구매 등 목표 행동 발생 | CVR, CPA, ROAS |
| `NEGATIVE_FEEDBACK` | 숨김, 신고, 바로 이탈 | 사용자 경험 감점 |

서버가 광고를 내려준 `SELECTED` 는 노출이 아니다. 사용자가 해당 위치까지 스크롤하지 않을 수 있기 때문이다.

그리고 사용자가 광고를 눌러 외부 URL을 열었을 때 기록하는 이벤트는 `VIEW` 보다는 `CLICK` 이 맞다. 이름을 잘못 지으면 나중에는 클릭률을 노출률이라고 부르는 기이한 대시보드가 탄생한다.

# 이벤트에는 어떤 데이터를 같이 저장할까?

각 이벤트에는 아래 값을 같이 저장할 예정이다.

```text
requestId
selectionId
campaignId
creativeId
placement
position
language
login 여부
현재 질문·학습 주제
기기 유형
시간대
appVersion
rankScore
scoreComponents
rankingPolicyVersion
modelVersion
experimentId / variant
occurredAt
```

`selectionId` 는 광고 선택부터 노출, 클릭, 전환까지 연결하는 핵심키로 사용한다. 동일 이벤트가 재전송될 수 있으니 이벤트 ID에는 unique key를 걸어서 멱등하게 적재한다.

랭킹 결과만 저장하는 것도 부족하다. `왜 이 광고가 1위였는지` 확인할 수 있도록 적합도, 예상 클릭률, 신규 광고 보너스, 반복 노출 감점 같은 점수 구성요소도 같이 저장해야한다.

모든 후보의 전체 로그를 무한정 저장하면 저장공간이 너무 커질 수 있다. 최종 선택 광고와 상위 후보의 점수는 항상 저장하고, 전체 후보와 탈락 사유는 일정 비율로 샘플링해서 저장하는 방식이 적절해보인다.

# 수집한 원본 데이터를 어떻게 가공할까?

원본 이벤트가 쌓였다고 바로 랭킹에 사용하면 안된다. 중복 이벤트, 봇, 반복 클릭, 전환 지연과 위치 편향부터 보정해야한다.

## 1. 중복과 비정상 이벤트 제거

* 동일 `eventId` 중복 제거
* 한 사용자의 짧은 시간 내 반복 클릭 제거
* 광고가 선택되지 않았는데 들어온 노출·클릭 이벤트 제거
* selection의 사용자·기기와 클릭 사용자가 다르면 제외
* 만료된 캠페인 또는 조작된 selection 제외

클릭이 많다고 전부 좋은 데이터가 아니다. 실수로 연속 탭했거나 자동화된 요청일 수도 있기 때문이다.

## 2. 유효 노출 판정

앱에서 광고의 50% 이상이 1초 이상 화면에 보였을 때 `VIEWABLE_IMPRESSION` 을 한 번만 전송한다.

```text
유효 노출 = selectionId 기준 최초 1회
```

피드가 다시 렌더링되거나 화면을 위아래로 움직였다고 노출수가 계속 증가하면 안된다. 새로운 피드 요청으로 새로운 `selectionId` 를 받았을 때만 별도 노출로 볼 수 있다.

## 3. 전환 귀속 기간 적용

광고를 클릭하고 바로 구매하지 않을 수 있다. 그래서 클릭 후 일정 기간 내 발생한 구매를 어떤 광고의 성과로 볼 것인지 정해야한다.

첫 버전은 아래처럼 단순하게 시작할 생각이다.

* 클릭 전환: 클릭 후 7일
* 노출 후 클릭 없는 전환: 별도 집계하되 랭킹 학습에는 우선 미사용
* 동일 사용자의 여러 광고 클릭: 마지막 유효 클릭에 귀속
* 구매 취소·환불: 전환 가치에서 차감

쿠팡 제휴 리포트와 구매 데이터를 연결할 수 없다면 일단 클릭까지만 최적화할 수 있다. 이 경우 `클릭이 많다 = 구매를 잘 만든다` 고 결론내리면 안된다.

## 4. 위치 편향 분리

피드 상단 광고는 하단 광고보다 당연히 많이 보이고 많이 클릭된다. 이 차이를 광고 소재의 품질로 학습하면 항상 상단에 있던 광고만 좋은 광고가 된다.

그래서 위치별 기본 CTR을 별도로 계산하고 광고 CTR을 같은 위치의 평균과 비교해야한다.

```text
상대 CTR = 광고의 위치별 CTR / 동일 위치 전체 광고 CTR
```

또는 A/B 테스트에서 광고 위치를 실험군마다 동일하게 고정해서 비교할 수 있다.

## 5. 데이터가 적은 광고는 평활화

신규 광고가 한 번 노출되어 한 번 클릭되면 CTR 100%가 된다. 그대로 랭킹하면 신규 광고가 갑자기 1위가 되고, 한 번 클릭되지 않으면 바로 바닥으로 떨어진다.

그래서 전체 광고의 평균을 사전값으로 넣어서 평활화한다.

```text
보정 CTR = (클릭수 + 사전 클릭수) / (유효 노출수 + 사전 노출수)
```

데이터가 적을 때는 전체 평균에 가깝고, 충분히 쌓이면 해당 광고의 실제 CTR에 가까워지는 구조다.

# 어떤 통계를 만들까?

| 지표 | 계산 | 의미 |
| --- | --- | --- |
| Fill Rate | 광고가 포함된 요청 / 광고 가능 요청 | 광고 재고가 충분한지 |
| Viewable Rate | 유효 노출 / 서버 선택 | 실제로 광고 위치까지 봤는지 |
| CTR | 클릭 / 유효 노출 | 광고가 클릭을 만든 정도 |
| Landing Rate | 랜딩 성공 / 클릭 | 딥링크와 외부 페이지가 정상인지 |
| CVR | 전환 / 클릭 | 클릭이 가입·구매로 이어진 정도 |
| eCPM | 광고 수익 / 유효 노출 × 1,000 | 지면 1,000회당 기대수익 |
| CPA | 광고 비용 / 전환 | 전환 하나를 만든 비용 |
| ROAS | 전환 금액 / 광고 비용 | 광고비 대비 매출 |
| Frequency | 사용자별 캠페인 노출수 | 동일 광고 반복 정도 |
| Fatigue | 빈도 증가에 따른 CTR·CVR 하락 | 광고 피로도 |
| Negative Rate | 숨김·신고 / 유효 노출 | 사용자에게 불편한 광고인지 |

여기서 CTR 하나만 높이는 것은 위험하다. 자극적인 제목으로 클릭은 많이 만들었지만 바로 뒤로가기를 누르거나 구매로 이어지지 않을 수 있다. 공개 질문 피드 자체의 체류시간과 좋아요가 떨어질 수도 있다.

그래서 광고 지표와 함께 아래 사용자 경험 지표를 가드레일로 둬야한다.

* 광고가 포함된 세션의 공개 질문 조회수
* 질문 좋아요와 댓글 참여율
* 광고 노출 직후 세션 이탈률
* 광고 숨김·신고율
* 다음날/7일 재방문율
* 피드 API 응답시간

# 어떤 광고를 잘 보여줄 것인가?

광고 선택은 먼저 노출 자격을 필터링하고, 그 다음 후보를 점수화하는 두 단계로 나누는 것이 좋다.

## 1. 노출 자격 필터

아래 조건은 가중치로 조정할 문제가 아니라 그냥 후보에서 제외해야한다.

* 캠페인이 활성 상태인가?
* 집행 시작·종료 시간 안에 있는가?
* 일 예산이나 노출 한도를 초과하지 않았는가?
* 로그인/비로그인 타겟이 맞는가?
* 지원하는 언어와 지면인가?
* 딥링크가 허용된 도메인인가?
* 동일 사용자 노출 간격과 일일 빈도 제한을 통과했는가?
* 피드에 광고를 넣을 수 있을 만큼 공개 질문이 충분한가?

## 2. 후보 광고 랭킹

초기에는 아래 형태의 설명 가능한 점수식으로 시작하는 것이 적절해보인다.

```text
최종 점수 =
    예상 광고 가치
  + 사용자·학습주제 적합도
  + 광고 품질
  + 신규 광고 탐색 보너스
  + 마지막 노출 이후 신선도
  - 오늘 반복 노출 감점
  - 광고 피로도
  - 숨김·신고·이탈 위험
```

쿠팡 제휴 구매 전환과 수수료를 받을 수 있다면 예상 광고 가치는 아래처럼 계산할 수 있다.

```text
예상 광고 가치 = 보정 pCTR × 보정 pCVR × 예상 구매 수수료
```

아직 구매 전환을 받을 수 없다면 보정 pCTR과 주제 적합도를 중심으로 시작한다. 단, 클릭만 최적화해서 공개 질문 경험을 망치지 않도록 이탈률과 부정 반응을 강한 감점으로 둔다.

사용자 적합도에는 현재 보고있는 질문의 주제, 사용자의 학습 주제, 언어, 이전 광고 반응을 사용할 수 있다. 예를 들어 Spring 질문을 보고있는 사용자에게 개발 서적이나 개발 장비 광고는 어느정도 맥락이 있지만, 전혀 관련없는 광고는 낮은 점수를 받게한다.

## 3. 탐색과 활용

항상 현재 1위 광고만 보여주면 신규 광고는 데이터를 얻을 수 없다. 반대로 완전 랜덤으로 보여주면 이미 성과가 낮다고 확인된 광고를 계속 노출하게 된다.

그래서 대부분은 현재 점수가 높은 광고를 보여주고 일부 트래픽만 데이터가 부족한 광고를 탐색한다.

```text
85%: 현재 점수 1위 광고
15%: 상위 후보 중 데이터가 부족한 광고 탐색
```

탐색도 전체 광고 랜덤이 아니라 품질과 타게팅 조건을 통과한 상위 후보 안에서만 수행한다. 광고가 충분히 노출되면 탐색 보너스는 줄어들어야한다.

# 모델을 어떻게 평가할까?

오프라인 평가와 실제 서비스 A/B 테스트를 분리한다.

오프라인에서는 과거 데이터의 시간 순서를 유지해서 학습과 검증 데이터를 나눈다. 미래 데이터를 섞어 학습하면 실제보다 성능이 좋게 나온다.

* Log Loss 또는 Brier Score
* AUC, PR-AUC
* 예측 CTR과 실제 CTR의 Calibration
* 언어·주제·위치·신규 캠페인별 성능
* 1일/7일 전환 지연을 반영한 성능

을 확인한다.

하지만 오프라인 지표가 좋아졌다고 바로 전체 배포하면 안된다. 실제 피드에서는 광고가 공개 질문 참여를 방해할 수 있기 때문이다.

A/B 테스트에서는 한 번에 하나의 요인만 변경한다.

```text
Control: 기존 규칙 기반 랭킹
Treatment: 새로운 pCTR + 적합도 랭킹
```

그리고 아래를 같이 본다.

* CTR과 CVR이 실제로 증가했는가?
* 광고 수익 또는 제휴 수수료가 증가했는가?
* 공개 질문 조회·좋아요가 감소하지 않았는가?
* 숨김, 신고, 세션 이탈이 증가하지 않았는가?
* 특정 언어·주제·사용자에게만 성과가 몰리지 않았는가?
* API latency가 증가하지 않았는가?

CTR은 올랐지만 공개 질문 참여와 재방문이 떨어진다면 좋은 광고 랭킹이라고 볼 수 없다.

# 정리

결국 광고 랭킹에서 모델보다 먼저 필요한 것은 올바른 집계 기준이다.

1. 서버 선택, 유효 노출, 클릭, 랜딩, 전환을 분리한다.
2. 유효 노출은 화면 50% 이상, 1초 이상을 기준으로 한다.
3. selectionId로 선택부터 전환까지 연결하고 멱등하게 저장한다.
4. 중복 클릭, 위치 편향, 신규 광고의 적은 표본, 전환 지연을 보정한다.
5. 예상 광고 가치와 사용자·주제 적합도를 더하고 피로도와 부정 반응을 감점한다.
6. 대부분은 좋은 광고를 활용하되 일부 트래픽은 제한적으로 탐색한다.
7. CTR만 보지 않고 공개 질문 참여와 재방문을 가드레일로 둔다.

데이터가 많지 않은 단계에서 복잡한 딥러닝 모델부터 도입하는 것은 순서가 아닌 것 같다. 먼저 이벤트 의미를 정확하게 나누고 설명 가능한 규칙 기반 랭킹과 평활화된 CTR을 운영한 뒤, 데이터가 충분히 쌓이면 Logistic Regression이나 Tree 기반 pCTR 모델을 붙이는게 적절해보인다.

아무리 좋은 모델을 만들어도 입력 데이터의 `노출`이 사실은 `서버가 내려준 횟수`이고 `view`가 사실은 `click`이라면 결과는 정교하게 틀릴 뿐이다.
